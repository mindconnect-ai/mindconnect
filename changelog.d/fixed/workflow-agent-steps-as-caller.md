- **Workflows**: an agent-call step asks the agent as the user the workflow runs for — the `ToolCallScope` of the run (an agent calling it as a tool, a scheduled job, a screen) — instead of the fixed `workflow` user, so the agent reaches that user's mail and connections; only a run on nobody's behalf still uses `workflow`. The step's session has the type `workflow` and stays out of the chat's history. A step waits at most `mindconnect.workflow.agent-call-timeout` (default ten minutes), and an agent that stops to ask for an approval fails the step with the tools it asked about, instead of blocking the run for good.
- **Workflows**: `WorkflowInputs.prepare(workflow, inputs, declaredOnly)` readies inputs for a run started from code, as the engine takes its params as they come: values are coerced to their declared types, a param left out gets its declared default, a missing required one is named before the run starts, and a caller offering a fixed set of values can keep only those the workflow declares.
